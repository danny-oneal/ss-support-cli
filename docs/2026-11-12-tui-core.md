# TUI Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A bare `ss-support` opens an interactive TUI: operation picker, parameter form, confirmation, live progress, result viewer with a semantic diff viewer, and an S3 browser that launches `s3.version-diff`.

**Architecture:** A `tui/` module in the `ss-support` crate, built on ratatui and crossterm. A Screen stack is driven by one event loop (`tokio::select!` over crossterm's `EventStream` and an `mpsc<Msg>`); `Screen::update` is pure state (no I/O), I/O is requested by returning `Cmd`s that the shell spawns. Operations run on a spawned task through the existing `Runner`; progress and confirmation reach the UI as `Msg`s, and confirmation is answered through a `oneshot`. The shell is generic over the ratatui `Backend` and the event stream so tests drive it with `TestBackend` and scripted keys.

**Tech Stack:** Rust 2024 (MSRV 1.88), ratatui 0.30, crossterm 0.29 (`event-stream`), futures-util, tokio, insta (plain-text snapshots).

**Spec:** `docs/2026-11-07-rust-port-master-plan.md` Phase 6 (key map and screen list), narrowed by the user's decisions of 2026-11-12 below. `docs/DESIGN.md` §5.5 and §7 for progress and views.

## Decisions (user-confirmed 2026-11-12 unless marked)

- Key map is the Phase 6 list, documented in the README by this plan.
- Scope: shell, picker, form, result, confirm, diffviewer, progress list, error panel, s3browse. `k8spods` and `logstail` are out; the picker's `p` key is unbound until they exist.
- Code lives in `crates/ss-support/src/tui/`; bare `ss-support` launches it when stdin and stdout are both terminals, otherwise it prints help as today. *(assistant's choice)*
- The TUI honors `--dry-run` and `--yes` exactly as the headless runner does. *(assistant's choice)*
- Commits are local Conventional Commits in the worktree; no push, no PR.

## Global Constraints

- Every public item has a doc comment (`missing_docs = "warn"`, clippy `-D warnings`); no `unwrap`/`expect`/indexing panics in `tui/` non-test code.
- Source comments, doc comments, test names describe behavior only: no mention of Go, the port, plans, phases, or reviews.
- Anything that reaches output uses `BTreeMap`; `async_trait` only on dyn-dispatched traits (`Screen` is sync, so none is needed).
- Library code never reads `std::env`; the shell receives everything through `Services`/`App`.
- Update `CHANGELOG.md` `[Unreleased]`; README key table must match behavior.
- Snapshots render at 80x24 into `TestBackend`; tests never touch a real terminal.

## Review Focus

1. A panic or error inside the TUI must still restore the terminal (raw mode off, alternate screen left). Pinned in Task 1 and Task 8.
2. Terminals smaller than 80x24 (down to 1x1) never panic: every screen renders a "terminal too small" notice or degrades. Pinned in Task 1.
3. Wide (CJK) and combining characters in the text input and tables keep the cursor and column widths correct. Pinned in Task 2.
4. Ctrl-C: during a run it cancels the run (exit path returns to the form with "cancelled"), during a confirmation it declines, elsewhere it quits; a run never keeps going after the UI has left. Pinned in Task 4.
5. S3 or other ports that are unconfigured or fail (suggestions, bucket list, run) show the error panel and keep the screen usable; they never end the TUI. Pinned in Tasks 5 and 7.

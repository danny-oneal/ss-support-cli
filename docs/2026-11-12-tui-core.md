# TUI Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A bare `ss-support` on a terminal opens an interactive TUI: operation picker, parameter form, confirmation, live progress, result viewer with a semantic diff viewer, and an S3 browser that hands two marked versions to `s3.version-diff`.

**Architecture:** A `tui/` module in the `ss-support` crate, built on ratatui and crossterm. A screen stack is driven by one event loop (`tokio::select!` over a crossterm event stream, an `mpsc<Envelope>` of async results, and the invocation's cancellation token). `Screen::update` is pure state; I/O is requested by returning `Cmd`s that the shell spawns, and every async result is routed back to the screen that asked for it. Operations run on a spawned task through the existing `Runner`; progress and confirmation reach the UI as `Msg`s and confirmation is answered through a `oneshot`. The shell is generic over the ratatui `Backend` and the event stream, so tests drive it with `TestBackend` and scripted keys.

**Tech Stack:** Rust 2024 (MSRV 1.88), ratatui 0.30, crossterm 0.29 (`event-stream`), futures-util 0.3, unicode-width 0.2, unicode-segmentation 1, tokio, insta (plain-text snapshots).

**Spec:** `docs/2026-11-07-rust-port-master-plan.md` Phase 6 (screen list and key map), narrowed by the decisions below; `docs/2026-11-12-finish-roadmap.md` milestone M1. `docs/DESIGN.md` §5.5 and §7 for progress and views.

## Decisions

User-confirmed on 2026-11-12:
- The key map is the Phase 6 list; this plan documents it in the README.
- Scope: shell, picker, form, result, confirm, diff viewer, progress list, error panel, S3 browser. The pods and log-tail screens are roadmap milestone M2; the picker's `p` key is unbound until then.
- Code lives in `crates/ss-support/src/tui/`; a bare `ss-support` launches it.
- Commits are local Conventional Commits in the worktree; no push, no PR.

Assistant's choices (redirect freely):
- The TUI opens only when stdin and stdout are both terminals; otherwise a bare invocation prints help as today.
- `--dry-run`, `--yes`, `--env`, `--profile`, `--region`, `--context`, and `--no-cache` apply to TUI runs exactly as they do headless. `-o`, `--export`, and `-v` have no effect in the TUI (export is the `e` key).
- Ctrl-C on the picker quits with exit 0, like `q`. SIGINT/SIGTERM/SIGHUP delivered as signals still exit 130.

## Validation record (2026-11-12)

The first draft of this plan was checked against the code and a compiled spike (ratatui 0.30.2, crossterm 0.29.0, `cargo +1.88 check` clean, one resolved version of each crate). Defects found and fixed in this revision:

| # | Defect in the draft | Fix |
|---|---|---|
| 1 | Launch decided on `std::io::stdin().is_terminal()`. `cargo test` run from a terminal would start a real TUI inside `bare_invocation_prints_help` and hang. | Terminal-ness is a field on `Io` (`Io::std()` detects, `Io::capture()` is `false`). Task 8. |
| 2 | End-to-end tests in `tests/tui.rs` could not reach a private `mod tui`. | Public `ss_support::run_tui_with(cli, services, &mut terminal, events) -> Exit`. Task 8. |
| 3 | `Ctx` held `Arc<App>`, but `App` is not `Clone` and `dispatch` only has `&App`. | `Ctx` owns clones of the `App` fields (all are `Arc`, `Clone`, or `String`). Task 1. |
| 4 | Runner warnings were forwarded as `Msg::Status`, which did not exist. | `Msg::Warning(String)`. Task 1. |
| 5 | Export needed a directory and a clock that `Ctx` did not carry, and `OpsResult` took `Meta` although `with_defaults` needs the operation. | `Ctx { export_dir, now }`; `OpsResult::new(op: Arc<dyn Operation>, ..)`. Tasks 1, 4. |
| 6 | `bridge::start` returned the cancel token to the shell, but the screen showing the run is what must cancel it. | The token travels in `RunRequest`, created by the progress screen. Tasks 3, 5. |
| 7 | Routing of async results to screens was unspecified. | The shell stamps each pushed screen with a `ScreenId`; results go to the issuing screen or are dropped, and a run whose screen is popped is cancelled. Task 1. |
| 8 | A test promised the shell survives a panicking operation. The release profile is `panic = "abort"`, so the process ends. | The promise is now: the terminal is restored before the process ends. Tasks 1, 8. |
| 9 | The second-signal path in `run()` calls `std::process::exit`, which skips `Drop` and would leave the terminal in raw mode. | One idempotent `tui::restore_terminal()` called from `Drop`, the panic hook, and that exit path. Task 1. |
| 10 | ratatui 0.30's `Backend` has an associated `Error`; the draft's `run_with` signature did not bound it. | `B::Error: std::error::Error + Send + Sync + 'static`. Task 1. |
| 11 | `TestBackend`'s `Display` appends "Hidden by multi-width symbols" notes for wide characters, which would pollute snapshots. | Snapshots use a `screen_text` helper that joins buffer rows. Task 1. |
| 12 | The S3 browser both "pushed a form" and "ran it". | It pushes the pre-filled form; the operator presses enter. Task 6. |
| 13 | Types were declared as placeholders in Task 1 and redefined later. | All message types are defined once in Task 1. |
| 14 | Tasks were ordered picker → bridge → form → result → browser, so the picker and the form each referred to screens that did not exist yet. | Tasks run in dependency order: bridge (3), result (4), form (5), browser (6), picker (7). No task needs a stand-in for a later one. |

## Global Constraints

- Every public item has a doc comment (`missing_docs = "warn"`, clippy `-D warnings`). No `unwrap`, `expect`, or panicking index in `tui/` outside tests.
- Source comments, doc comments, and test names describe behavior only: no mention of Go, the port, plans, phases, or reviews.
- Anything that reaches output uses `BTreeMap`. `Screen` is a sync trait, so no `async_trait`.
- Library code never reads `std::env`; the shell receives everything through `Services`, `App`, and `Io`.
- Use crossterm through `ratatui::crossterm`; the direct `crossterm` dependency exists only to enable `event-stream`.
- Update `CHANGELOG.md` `[Unreleased]`; the README key table and command list must match behavior.
- Snapshots render at 80x24 into `TestBackend` through `screen_text`; tests never touch a real terminal.
- `make check` and `make msrv` pass at every commit.

## Review Focus

1. Every way out of the TUI restores the terminal: normal quit, error, panic (the release profile aborts), SIGTERM/SIGHUP, and a second signal. Pinned in Tasks 1 and 8.
2. Terminals smaller than 80x24, down to 1x1, never panic. Pinned in Task 1.
3. Wide (CJK) and combining characters in inputs and tables keep the cursor and columns correct. Pinned in Tasks 2 and 4.
4. Ctrl-C cancels a run, declines a confirmation, and quits only from the picker; a run never continues after its screen is gone. Pinned in Tasks 1, 3, and 5.
5. An unconfigured or failing port (suggestions, listings, a run) shows an error and leaves the screen usable. Pinned in Tasks 5 and 6.
6. A run started from the TUI passes through the same guard, confirmation, and audit log as a headless run. Pinned in Tasks 3 and 8.
7. Text from outside (object bodies, item values, keys, error messages) cannot drive the terminal: escape sequences are inert and tabs do not vanish. Pinned in Task 4.

Layout: title bar `ss-support · <env name> · <title>`, body, status bar with `hints()` and the last status text. Below 20x6 only "terminal too small" is drawn.
